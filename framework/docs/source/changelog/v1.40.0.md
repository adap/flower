### What's new?

- **Connect SuperNodes to the Fleet API over HTTP** ([#8301](https://github.com/flwrlabs/flower/pull/8301), [#8303](https://github.com/flwrlabs/flower/pull/8303), [#8304](https://github.com/flwrlabs/flower/pull/8304), [#8305](https://github.com/flwrlabs/flower/pull/8305), [#8307](https://github.com/flwrlabs/flower/pull/8307), [#8308](https://github.com/flwrlabs/flower/pull/8308), [#8309](https://github.com/flwrlabs/flower/pull/8309), [#8310](https://github.com/flwrlabs/flower/pull/8310), [#8311](https://github.com/flwrlabs/flower/pull/8311), [#8313](https://github.com/flwrlabs/flower/pull/8313), [#8314](https://github.com/flwrlabs/flower/pull/8314), [#8315](https://github.com/flwrlabs/flower/pull/8315), [#8316](https://github.com/flwrlabs/flower/pull/8316), [#8317](https://github.com/flwrlabs/flower/pull/8317), [#8318](https://github.com/flwrlabs/flower/pull/8318), [#8320](https://github.com/flwrlabs/flower/pull/8320), [#8321](https://github.com/flwrlabs/flower/pull/8321), [#8322](https://github.com/flwrlabs/flower/pull/8322), [#8325](https://github.com/flwrlabs/flower/pull/8325), [#8333](https://github.com/flwrlabs/flower/pull/8333))

  SuperNodes now connect to the Fleet API over HTTP on the SuperLink's shared `--host` and `--port`, using port `8000` by default. The HTTP API supports SuperNode authentication, version checks, and event logging. SuperLink no longer enables the gRPC Fleet API by default, its `--fleet-api-type` and `--fleet-api-address` options are deprecated, and SuperNode no longer accepts the `--grpc-rere` and `--grpc-adapter` transport options.

- **Search Slack and query Notion meeting notes** ([#8264](https://github.com/flwrlabs/flower/pull/8264), [#8290](https://github.com/flwrlabs/flower/pull/8290), [#8306](https://github.com/flwrlabs/flower/pull/8306), [#8323](https://github.com/flwrlabs/flower/pull/8323))

  Search public Slack channels and, when access allows, private conversations. You can also filter Notion AI meeting notes to find relevant notes, with clearer guidance on finding and reading their contents.

- **Continue conversations in `@flwrlabs/agent` app** ([#8274](https://github.com/flwrlabs/flower/pull/8274))

  The [@flwrlabs/agent](https://flower.ai/apps/flwrlabs/agent) in Flower Hub now now allows follow-up prompts to retain context across runs in the same conversation. This app is a minimal agent that you can extend easily for your particular use case.

- **Set federation icons** ([#8273](https://github.com/flwrlabs/flower/pull/8273))

  Federations can now store an optional icon key, update or clear it. This helps identifying federations.

- **Set up Endeavor with a Flower API key** ([#8324](https://github.com/flwrlabs/flower/pull/8324))

  The Endeavor documentation now includes a dedicated Flower API key setup guide for the macOS CLI and desktop app, with clearer navigation across the Codex and OpenCode guides. Read more in the [Endeavor 1.0](https://flower.ai/docs/model/endeavor.html) documentation.

- **Use accurate OpenAPI schemas for protobuf-over-HTTP APIs** ([#8037](https://github.com/flwrlabs/flower/pull/8037))

  OpenAPI documentation for Control and Runtime protobuf-over-HTTP routes now preserves endpoint descriptions and advertises their actual binary request and response formats instead of empty JSON responses. Runtime request handling and protobuf serialization remain unchanged.

- **Build Python foundation images with updated security packages** ([#8340](https://github.com/flwrlabs/flower/pull/8340))

  Python foundation image builds now upgrade installed Ubuntu packages and apply the configured `pip` and `setuptools` versions to both the managed Python installation and the virtual environment. Rebuild the foundation and downstream images with refreshed package layers to pick up the updates; builds may take longer and depend on available `apt` updates.

- **General improvements** ([#8269](https://github.com/flwrlabs/flower/pull/8269), [#8276](https://github.com/flwrlabs/flower/pull/8276), [#8277](https://github.com/flwrlabs/flower/pull/8277), [#8278](https://github.com/flwrlabs/flower/pull/8278), [#8281](https://github.com/flwrlabs/flower/pull/8281), [#8286](https://github.com/flwrlabs/flower/pull/8286), [#8289](https://github.com/flwrlabs/flower/pull/8289), [#8312](https://github.com/flwrlabs/flower/pull/8312), [#8326](https://github.com/flwrlabs/flower/pull/8326), [#8332](https://github.com/flwrlabs/flower/pull/8332), [#8334](https://github.com/flwrlabs/flower/pull/8334), [#8342](https://github.com/flwrlabs/flower/pull/8342))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.
