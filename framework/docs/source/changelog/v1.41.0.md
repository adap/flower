### What's new?

- **Use GitHub, Notion, Slack, Attio, and Google connectors through MCP** ([#8328](https://github.com/flwrlabs/flower/pull/8328), [#8339](https://github.com/flwrlabs/flower/pull/8339), [#8343](https://github.com/flwrlabs/flower/pull/8343), [#8362](https://github.com/flwrlabs/flower/pull/8362), [#8382](https://github.com/flwrlabs/flower/pull/8382))

  GitHub, Notion, Slack, and Attio connectors now integrate through MCP, with tools discovered dynamically from each connected account. New Google Drive, Gmail, and Google Calendar connectors use Google's remote MCP servers with OAuth/PKCE and token refresh.

- **Keep connector-backed AgentApps running through credential and availability changes** ([#8366](https://github.com/flwrlabs/flower/pull/8366), [#8372](https://github.com/flwrlabs/flower/pull/8372), [#8373](https://github.com/flwrlabs/flower/pull/8373), [#8384](https://github.com/flwrlabs/flower/pull/8384))

  SuperLink now refreshes opted-in OAuth credentials before connector tasks receive them. Tool discovery skips connectors that are unavailable for a run while continuing with available tools, preserves the specific availability error through HTTP retries, and reports Slack MCP failures with status and error details while redacting tokens.

- **Store and reuse compacted AgentApp contexts** ([#8350](https://github.com/flwrlabs/flower/pull/8350), [#8363](https://github.com/flwrlabs/flower/pull/8363), [#8364](https://github.com/flwrlabs/flower/pull/8364), [#8367](https://github.com/flwrlabs/flower/pull/8367), [#8370](https://github.com/flwrlabs/flower/pull/8370), [#8371](https://github.com/flwrlabs/flower/pull/8371), [#8376](https://github.com/flwrlabs/flower/pull/8376), [#8377](https://github.com/flwrlabs/flower/pull/8377), [#8380](https://github.com/flwrlabs/flower/pull/8380))

  AgentApps can now filter run-series events and read or store compacted contexts through `AgentSession.events`. Compacted contexts are persisted per run series and exposed through authenticated Runtime API endpoints with newest-first paginated reads.

- **Connect SuperNodes to SuperGrid with valid addresses** ([#8359](https://github.com/flwrlabs/flower/pull/8359), [#8360](https://github.com/flwrlabs/flower/pull/8360))

  Current SuperGrid connection examples now use `api.flower.ai:443`. SuperNode rejects addresses with URL prefixes before connecting; omit `http://` and `https://`, since HTTPS is the default and `--insecure` selects HTTP.

- **Measure AgentApp execution latency in greater detail** ([#8375](https://github.com/flwrlabs/flower/pull/8375), [#8388](https://github.com/flwrlabs/flower/pull/8388))

  Agent execution traces now include metadata-only spans for task initialization, AgentApp preparation, model round trips, cleanup, warm-dispatch phases, and provider first-text latency, together with requested model and token-count metadata. Execution flow and trace propagation remain unchanged.

- **Prepare destination-oriented message delivery** ([#8349](https://github.com/flwrlabs/flower/pull/8349), [#8358](https://github.com/flwrlabs/flower/pull/8358), [#8374](https://github.com/flwrlabs/flower/pull/8374), [#8378](https://github.com/flwrlabs/flower/pull/8378), [#8387](https://github.com/flwrlabs/flower/pull/8387))

  `CoreState` now defines and implements destination-based message storage, retrieval, acknowledgment, and cancellation across its in-memory and SQL backends, backed by a unified message schema and shared `LinkState` policy checks. This prepares a future transport cutover while retaining legacy `NodeState` retrieval as `get_messages_legacy`.

- **Support 64-bit task event IDs on PostgreSQL** ([#8365](https://github.com/flwrlabs/flower/pull/8365))

  PostgreSQL deployments now use signed 64-bit IDs for task events, removing the previous signed 32-bit sequence limit. SQLite retains its existing 64-bit integer behavior.

- **General improvements** ([#8341](https://github.com/flwrlabs/flower/pull/8341), [#8356](https://github.com/flwrlabs/flower/pull/8356), [#8357](https://github.com/flwrlabs/flower/pull/8357), [#8361](https://github.com/flwrlabs/flower/pull/8361), [#8389](https://github.com/flwrlabs/flower/pull/8389))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.
